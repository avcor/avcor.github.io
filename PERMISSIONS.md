# Claude Code — Pre-approved Commands

This file documents the command patterns allowlisted in `.claude/settings.json`
so Claude doesn't have to ask permission for them on every session. It's
generated by scanning past session transcripts for commands that were
repeatedly approved, then extended on request.

| Pattern | Times seen | What it's for |
|---|---|---|
| `Bash(npx tsc *)` | 57 | TypeScript typecheck (`--noEmit`), verifies changes compile cleanly |
| `Bash(npm run dev *)` | 51+ | Starts the local Vite dev server (fixed `dev` script, any `--port`) so a page can be screenshotted/verified |
| `Bash(google-chrome --headless *)` | 50 | Headless Chrome screenshots for visually verifying UI changes |
| `Bash(./node_modules/.bin/tsc *)` | 31 | Typecheck via the local `tsc` binary directly |
| `Bash(curl -s http://localhost:*)` | 27 | Checks whether the local dev server has come up |
| `Bash(curl -sf http://localhost:*)` | — | Same as above, `-f` variant used in readiness-polling loops |
| `Bash(rm -rf *)` | — | Removing scratch files, stale build output, temp dirs |
| `Bash(mkdir -p *)` | — | Creating new component/asset folders |
| `Bash(npm install *)` | — | Adding a dependency (e.g. `react-icons`) |
| `Bash(npm init *)` | — | Scaffolding a throwaway `package.json` (e.g. in a scratchpad) |
| `Bash(pkill *)` | — | Killing background dev-server processes started during verification |
| `Bash(git stash)` / `Bash(git stash pop)` | — | Temporarily shelving changes (e.g. to confirm a bug pre-dates the current edit) |
| `Skill(run)` | — | The `run` skill, used to launch and drive the dev server for visual verification |

## Explicitly *not* allowlisted

- **`node <script>.js` / `node -e ...`, `python3 -c ...`, `bash -c ...`** —
  these are interpreters: a wildcard here is equivalent to unrestricted code
  execution, not just a risky file operation. Each invocation still prompts,
  even though `node` scripts show up constantly in this workflow (ad-hoc
  Playwright/measurement scripts in the scratchpad). If this gets too noisy,
  the safer middle ground is allowlisting specific scratchpad script names
  once they stabilize, not `node *`.
- **`npm run <script>` with a wildcarded script name** — only the fixed
  `dev` script is allowlisted; other scripts could run arbitrary
  project-defined commands.
- Already covered by Claude Code's own built-in auto-allow list, so no
  entry is needed: `find`, `grep`, `cat`, `ls`, `git status`, `git diff`,
  `git log`, `git show`, `head`, `tail`, `sed`, `sort`, `wc`, `echo`, `sleep`.

## Note on scope

`Bash(rm -rf *)`, `Bash(mkdir -p *)`, `Bash(npm install *)`, `Bash(npm init *)`,
and `Bash(pkill *)` are **not read-only** — they were added at explicit
request, overriding the usual "read-only only" default. They're scoped to
this project's `.claude/settings.json`, so they only affect sessions rooted
here.

## Updating this list

Re-run the `fewer-permission-prompts` skill periodically (or ask Claude to
"scan for permission prompts to allowlist") to pick up new recurring
patterns as the workflow evolves. Keep this file and `.claude/settings.json`
in sync — this file is documentation, `.claude/settings.json` is what
Claude Code actually reads to decide whether to prompt.
